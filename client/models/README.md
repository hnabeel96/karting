# Swapping in 3D models

Everything in the game is drawn by code until you list a model file in `manifest.js`. Then that file is used instead, and everything else stays as it was. If a file fails to load, the game falls back to the built-in art and prints a warning in the browser console.

## Quick start

1. Export your model from Blender (File → Export → glTF 2.0, format **glTF Binary (.glb)**), or download one. Kenney (kenney.nl) and Quaternius (quaternius.com) models are free to use (CC0).
2. Put the `.glb` in this folder.
3. Point the matching entry in `manifest.js` at it, e.g. `palm: { file: 'palm.glb' }`.
4. Refresh the game.

To see a swap working before making your own, add `#examples` to the game's address. It loads the blocky models in `examples/`.

## What can be swapped

| Entry | What it replaces | Size it is used at |
|---|---|---|
| `kart` | the kart and driver | resized so its longest side is 2.6 m, then times `scale` |
| `crate` | breakable crates | resized to 1.6 m, then times `scale` |
| `mango` | mango pickups | resized to 1 m, then times `scale` |
| `temple`, `ruin`, `pillar`, `palm`, `rock` | arena props | as modelled, in metres (1 Blender unit = 1 m), times `scale` |

Options for any entry: `scale`, `rotateY` (degrees), `y` (metres up or down), `fit: 'footprint'`, `randomYaw`. The kart also takes `length` (metres, default 2.6).

## Rules for any model

- **Facing:** the front points along glTF +Z. In Blender that means the front faces −Y (you see the front in Blender's Front view, numpad 1). If a model comes out backwards, use `rotateY: 180` instead of re-exporting.
- **Ground:** the game stands every model on the ground and centres it, so the origin can be anywhere.
- **Keep it light:** phones draw this. Aim for under 3,000 triangles per prop and under 10,000 for the kart, with as few separate materials as you can. Every copy of a prop shares one draw call per material, so 8 palms cost the same as 1.
- **Textures:** fine, but keep them at 1024×1024 or smaller.

## Lining models up with collisions

What karts bump into is defined by the shapes in `shared/arenas/temple.js`, not by the model. A bigger pillar model does not make the pillar harder to drive through. Two ways to keep them matched:

- Use `fit: 'footprint'` to stretch a model sideways so it exactly covers its shape (good for walls).
- Or change the shape's size in the arena file to match the model.

To check, open the browser console while playing and type `karting.colliders = true`. Every collision shape is outlined in pink.

## The kart contract

The kart moves in parts, so the game looks for these node names (object names in Blender):

| Name | Required | What happens to it |
|---|---|---|
| `wheel_fl`, `wheel_fr` | yes | spin, and steer left/right. Origin must be at the axle centre, axle along X |
| `wheel_rl`, `wheel_rr` | yes | spin. Same origin rule. Skid marks start under these |
| `driver` | no | leans into corners and back when boosting |
| `head` | no | turns to look into corners |
| `exhaust_l`, `exhaust_r` | no | empties marking where boost flames come out; otherwise the back of the model is used |

Everything else (the body, the seat, the driver if it is not named) squashes and tilts with the kart. A material named `paint` is recoloured to each player's colour, so one kart model works for all eight players.

Missing wheels do not break anything: they just do not spin. Look in the browser console for a warning naming any part it could not find.

`examples/blocky-kart.glb` follows this contract; open it in Blender to see the setup. The example files are generated by `scripts/make-example-models.mjs`.
